# ドキュメントの位置付け

Rhinestoneのドキュメントには、現在使える機能の案内と、過去・将来の設計資料が含まれます。
迷ったときは、実装とテストに一致する「現行の公開契約」を参照してください。

## 現行の公開契約

利用者向けの現行契約は、ナビゲーションに掲載されたガイドとAPIリファレンスです。公開APIの正確なシグネチャと振る舞いは、`src/rhinestone/`の実装および`tests/`のテストと一致しなければなりません。

- [はじめに](getting-started.md)
- [ガイド](search.md)
- [目的別チュートリアル](tutorials/index.md)
- [APIリファレンス](api.md)
- [対応状況](compatibility.md)
- [Runtimeの導入ガイド](runtimes.md)
- [API安定性とリリース運用](release-policy.md)

文書と実装が矛盾する場合は、実装とテストを確認し、同じ変更で公開ドキュメントを更新します。

## 移行先の設計草案

`spec_v5.md`はv0.5へ段階的に移行するための設計草案です。将来の方向性を示しますが、未実装のAPIや現在と異なる例を含むため、現行の公開契約ではありません。実装済みになった内容は、公開ガイド、APIリファレンス、テストへ反映してから現行契約として扱います。

主要な設計判断の実装・延期・置換状況は
[v0.5 実装状態マトリクス](v05-status-matrix.md)で追跡します。マトリクスは移行状況の
索引であり、それ自体を公開APIの正本にはしません。

## 履歴資料

次の文書は、過去の設計判断や実装計画を保存する履歴資料です。現行APIの利用方法や新しい変更の規範としては使用しません。

特に `spec_v4.md` は当時の仕様を保存するための凍結資料です。現行実装に合わせて更新せず、
現在の挙動を確認するときは上の公開ガイドとAPIリファレンスを参照します。

- `spec_v4.md`（凍結。内容を変更しない）
- `adapter_expansion.md`
- `architecture/`
- `specs/`

これらはMkDocsのナビゲーションと公開ビルド対象から除外します。履歴資料を参照する場合は、現行の実装、テスト、公開ドキュメントとの差分を確認してください。

## 開発時の更新規則

- 公開APIや振る舞いを変更する場合は、実装、テスト、該当する公開ガイド/APIリファレンスを同じ変更で更新します。
- v0.5の設計判断を実装する場合は、設計草案だけで完了とせず、現行の公開契約へ反映します。
- 過去の判断を保存する目的以外で履歴資料へ新しい契約を追加しません。
- Pythonサポート範囲は`pyproject.toml`を正本とし、現在はPython 3.10以上です。CIで検証するバージョンは[対応状況](compatibility.md)に記載します。
